Результат технического прохода по 237 публикациям: 2587 непустых разделов. Полная методика и ограничения — [CORPUS_AUDIT.md](../../CORPUS_AUDIT.md).

Одна строка JSONL — один раздел авторского HTML между разделителями. block_id состоит из post_id и номера раздела. candidate_links — число строк прежнего сборщика, а не число товаров. labels — подписи ссылок; для 13 восстановленных разделов это вручную составленная краткая метка. source_url ведёт к авторскому посту, не к магазину. excerpt — начало раздела, не обязательно весь доказательный контекст.

status и origin — результат первичной сортировки. review_level различает автоматическую сортировку и точечную ручную проверку; ни один из них сам по себе не подтверждает точное число вещей в блоке. text_flags — словесные признаки: будущее «куплю» не означает состоявшуюся покупку, «у меня» может относиться к предшествующей модели. Категории являются подсказками, пересекаются и покрывают не все строки.

Запуск из каталога research/products с доступными локальными входными файлами:

```sh
python audit_corpus.py --input-dir /path/to/saved-corpus --output-dir data/census
```

Скрипт не обращается к сети и не раскрывает короткие ссылки. Сохранённые числовые итоги всегда сопровождаются единицей учёта. Не превращать техническую полноту реестра в заявление о полном ручном анализе.
